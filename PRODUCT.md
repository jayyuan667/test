# Product

## Register

product

## Users

Primary users are manufacturing process engineers, enterprise administrators, and platform administrators working in an authenticated operational tool. Engineers upload 2D drawings, review extracted features, generate process plans, export deliverables, and save validated records into a reusable process library. Enterprise administrators manage users, quotas, and their company's records. Super administrators operate the whole platform across enterprises.

## Product Purpose

The product is an AI-assisted 2D process planning system for PDF, image, and PRT drawing analysis. It should help teams turn engineering drawings into reviewable process plans, reusable knowledge-base records, and exportable process files while enforcing enterprise-level data isolation.

Success means users can complete daily workflow tasks without ambiguity: upload, review, generate, edit, export, save to library, browse records, and manage access. The system should make role boundaries obvious and prevent accidental cross-enterprise exposure.

## Brand Personality

Precise, restrained, trustworthy.

The interface should feel like a professional engineering workstation: calm, readable, efficient, and predictable. It should avoid decorative spectacle and keep attention on task state, data quality, and action clarity.

## Anti-references

Do not make the product feel like a marketing landing page, a playful consumer app, or a decorative AI demo. Avoid oversized hero sections, generic glass cards, gratuitous gradients, confusing icon-only actions, hidden hover-only controls, and modal-heavy workflows where inline controls are enough.

Avoid permission UI that implies broader access than the backend grants. Avoid "platform" or "all enterprise" language for enterprise administrators.

## Design Principles

1. Less is more: add the smallest control that makes the task clear.
2. Familiarity beats novelty: use standard tables, selects, buttons, tabs, and dialogs.
3. Permissions must be visible in the workflow: role boundaries should be explicit before an action fails.
4. Data integrity before polish: exports, library records, and process rows must match what the user sees.
5. Quiet motion only: animation explains state changes and never slows task work.

## Accessibility & Inclusion

Target WCAG AA for text contrast, focus visibility, keyboard access, and form feedback. Interactive controls should have at least 44px touch targets where practical. Motion must respect reduced-motion preferences. Error messages should state the failed action and recovery path.
