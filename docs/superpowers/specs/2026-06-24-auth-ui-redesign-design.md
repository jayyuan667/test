# 认证入口 UI 重构设计

**日期：** 2026-06-24
**分支：** `yolo-react`
**状态：** 设计完成，待评审

## 目标

在不改变现有认证逻辑、角色体系、接口协议和页面切换方式的前提下，重写登录/注册页的前端表现，使其具备更强的完成度和记忆点，同时继续服务于“二维工艺系统”的产品定位。

本次设计不是把认证页做成营销页，也不是复刻 Rive 风格演示，而是在现有工业软件视觉系统内，引入更高级的聚焦光感、层次感和受控动效。

## 设计结论

采用“**检视台**”作为主隐喻，混入少量“**控制台**”语言：

- 左侧或主区承担登录/注册的核心操作，保持稳定、清晰、可交付
- 右侧或辅区承担视觉记忆点，表现为“图纸被聚光灯照亮的检视台”
- 少量引入刻度、准星、扫描束、层板投影等工业细节
- 只借鉴 Rive / 灯光登录页 / 页面跃迁案例中的“层次、聚焦和轻动势”，不照搬其夸张舞台感

## 非目标

- 不改后端认证接口
- 不引入 `react-router`
- 不重构 `AuthContext` 认证流程
- 不在本次设计内处理 Toast 全局化以外的认证逻辑缺陷
- 不把登录页做成高负载交互动画容器
- 不为了视觉效果引入明显吃性能的持续渲染运行时

## 当前基线

现有产品已形成明确基线：

- 页面主色系为 `slate / navy / flame`
- 工具属性强于品牌展示属性
- 主应用界面以侧栏、卡片、表格、状态标签构成
- 交互偏桌面优先，强调任务完成效率

登录/注册页当前问题：

1. 结构过于普通，与主应用的完成度不匹配
2. 只有基本表单，没有形成“系统入口”的品牌识别
3. 页面视觉与主应用之间存在轻微割裂，像独立表单而非控制台入口
4. 趣味度几乎为零，但又不具备足够强的工业精密感

## 用户与场景

目标用户仍然是工艺工程师、审核人员、知识库维护人员。

他们在进入系统时的预期不是“被惊艳”，而是：

- 快速识别自己进入的是正确系统
- 低成本完成登录或注册
- 在视觉上感受到系统稳定、专业、可信

因此认证页的设计标准应为：

- 第一优先级：可读、可用、清晰
- 第二优先级：品牌感和精致度
- 第三优先级：记忆点

## 设计方向

### 1. 总体布局

采用双区布局：

- **表单区**：承担所有主操作和错误反馈
- **视觉区**：承担主题表达和轻量动效

桌面端：

- 左右双栏
- 表单区宽度稳定，避免过宽导致表单松散
- 视觉区可更自由，但不能喧宾夺主

移动端：

- 退化为单栏
- 视觉区压缩为顶部氛围模块或弱化背景
- 表单区优先保证首屏完成登录

### 2. 视觉隐喻

主隐喻为“图纸检视台”：

- 深色背景模拟工作台或夜间检视环境
- 中央或偏右区域存在一束受控聚光
- 图纸层片、轮廓框、辅助标尺、轻量投影构成空间感
- 局部橙色高亮只用于焦点、激活和关键动作

少量控制台元素：

- 环形或线性刻度
- 准星/定位角标
- 状态脉冲点
- 低频扫描线

禁止元素：

- 紫蓝霓虹
- 大面积玻璃拟态
- 角色化卡通物件
- 重度宇宙/失重表演
- 与工艺系统无关的潮流图形

### 3. 色彩策略

继续使用现有色彩体系：

- 背景基底：冷灰、海军蓝
- 主文本：深 slate
- 主动作：暖橙
- 强调反馈：仅在焦点、按钮、扫描和激活态出现

约束：

- 登录页不得引入新的品牌主色
- 动态视觉区允许出现更深的 navy 层次，但不允许演变成纯黑科幻场景
- 橙色用于聚焦与操作，不做大面积装饰漫灌

## 组件设计

### 1. 登录页

登录页应由以下内容构成：

- 品牌识别
- 标题与简短说明
- 用户名输入
- 密码输入
- 错误反馈
- 登录按钮
- 注册切换入口
- 页脚信息

设计要求：

- 表单容器具备“面板”属性，不只是白色卡片
- 视觉权重集中在标题、当前聚焦字段和主按钮
- 密码显隐按钮继续保留
- 错误信息维持内联表达，不依赖 Toast

### 2. 注册页

注册页与登录页使用同一套骨架和语言，只替换内容和表单结构。

要求：

- 与登录页共享视觉区和布局系统
- 注册页不单独发明另一套装饰
- 字段增多时保持垂直节奏稳定
- 注册成功后的反馈路径在未来 Toast 全局化后可自然接入

### 3. 视觉区

视觉区不是插画容器，而是一个“主题化状态背景”。

应包含：

- 一束或一片聚焦光
- 一到两层图纸/检视板层片
- 少量工业辅助图形
- 低幅动态反馈

不应包含：

- 大量说明文案
- 复杂操作控件
- 分散注意力的高频动画

## 动效策略

### 动效目标

动效只承担三类责任：

1. 首屏进入时建立氛围
2. 用户聚焦输入时提供轻反馈
3. 页面在登录与注册之间切换时保持连续感

### 动效方案

- 首屏入场：表单淡入上移，聚光从暗到明，图纸层轻微错位进入
- Hover/Focus：输入聚焦时，视觉区出现轻微扫描或刻度点亮
- 页面切换：登录/注册切换采用受控的淡入位移，不做夸张翻页
- 按钮反馈：保留现有按压反馈，增强 hover 光泽的一致性

### 性能约束

- 优先使用 CSS 与 GSAP 实现一次性或低频动画
- 禁止持续高成本粒子或逐帧复杂路径动画
- 禁止因为登录页而引入沉重运行时
- reduced-motion 下退化为静态层次 + 简单淡入

### Rive 使用策略

本次设计不以“接入真实 Rive 文件”为前提。

策略如下：

1. 优先用现有前端能力实现 Rive 风格的层次与动势
2. 如果后续存在明确收益且资源可控，再评估局部接入 Rive 资产
3. 若引入真实 Rive，必须满足：
   - 首屏不明显拖慢
   - 降级路径清晰
   - 视觉内容仍然服务主题而非成为主角

## 架构边界

本次改动必须避免架构偏移。

允许改动：

- `frontend-react/src/pages/LoginPage.tsx`
- `frontend-react/src/pages/RegisterPage.tsx`
- 认证页相关的共享样式与局部组件抽取
- 必要的动效封装

谨慎改动：

- `frontend-react/src/index.css`
- Toast 相关共享层

不改动：

- 认证 API 协议
- `AuthContext` 状态机
- 主应用导航结构
- 已有页面路由模型（`useState` 切页）

如果实现过程中出现以下偏移，必须立即回退修正：

- 为认证页单独创造与主应用冲突的设计系统
- 新增只服务单页炫技的重量级依赖
- 视觉区占据主交互优先级
- 注册页与登录页风格断裂

## 实施建议

### 推荐拆分

1. 先抽出认证页共享骨架
2. 再实现登录/注册表单内容
3. 再补视觉区层次
4. 最后补受控动效与 reduced-motion 退化

### 可能新增的前端结构

- `components/auth/AuthShell`
- `components/auth/AuthVisualStage`
- `components/auth/AuthBrandBlock`

是否抽组件以实现时实际复杂度为准，但目标是避免登录页和注册页各自复制大段结构。

## 测试与验证

必须验证：

- 桌面端登录页布局
- 移动端首屏可用性
- 键盘 tab 顺序和焦点态
- 错误信息可见性
- `prefers-reduced-motion` 下的退化
- 构建通过

建议验证：

- 登录/注册切换时的视觉连续性
- 低性能设备上的动画流畅性
- 与主应用界面的视觉衔接是否自然

## 验收标准

满足以下条件方可视为完成：

1. 登录/注册页明显比当前更完整、更有产品质感
2. 视觉记忆点与“二维工艺系统”主题相关，而非泛化炫技
3. 主交互效率不下降
4. 不引入明显性能负担
5. 与主应用的色彩、控件和气质保持一致

## 风险与对策

### 风险 1：视觉过头

表现：

- 视觉区比表单更抢眼
- 看起来像活动页或概念页

对策：

- 优先保证表单区对比度和层级
- 控制运动频率与亮度
- 所有橙色高亮只服务焦点和动作

### 风险 2：和主应用脱节

表现：

- 登录页像另一套品牌系统

对策：

- 复用现有 token、按钮、输入框逻辑
- 所有新增样式从现有 palette 推导

### 风险 3：性能开销不值

表现：

- 首屏动画拖慢
- 动效收益小于成本

对策：

- 优先静态层次和低频动画
- 如果真实 Rive 接入收益不明显，则不接
