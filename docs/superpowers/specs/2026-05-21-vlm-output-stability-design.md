# VLM 图纸提取输出稳定性优化 — 设计规格

**日期：** 2026-05-21
**文件：** `backend/pipeline/vlm_feature.py`
**范围：** Prompt 指令优化 + 输出规范化层 + 关键字段校验

---

## 问题

同一零件每次 VLM 提取结果不一致，三类问题混合出现：

1. **字段缺失/格式混乱** — 字段时有时无，排版格式每次不同
2. **数值波动** — 同一张图同一尺寸，每次读出的数字有微小偏差
3. **公差漏读** — `【尺寸公差】【形位公差】` 频繁返回"无"

根因：
- Prompt 对多视图外形尺寸合并、公差扫描位置没有明确指令
- VLM 输出后没有硬规范化，自由文本直接透传
- 对明显异常值没有拦截机制

---

## 目标

- **同一组图多次调用 VLM，输出字段集合和格式完全一致**（缓存层保障）
- **外形尺寸数值偏差控制在 ±2mm 以内**（规范化 + 波动锁保障）
- **公差字段漏读率显著降低**（Prompt 指令保障）

---

## 不在范围内

- 不修改 `_merge_geometry_creo_vlm_fields` 的合并优先级逻辑
- 不修改 `_apply_drawing_size_reference_to_lwh` 纠偏算法
- 不修改 `_anchor_occ_lwh_to_creo` 锚定算法
- 不引入两轮 VLM 调用
- 不改变对外接口签名

---

## 设计

### 改动 1 — Prompt 指令优化

**文件位置：** `vlm_feature.py` 第 59–84 行，`_VLM_ENGINEERING_DRAWING_PROMPT` 常量

**修改内容：**

`【外形尺寸】` 从单行指令改为三步链式推理：

```
【外形尺寸】
第一步：识别每张图的视图类型（主视图/左视图/右视图/俯视图/剖视图/其他）
第二步：按视图类型提取轴向尺寸
  - 主视图 → 长方向和高方向的最大外轮廓标注值
  - 左视图/右视图 → 宽（厚度）方向和高方向的最大外轮廓标注值
  - 俯视图 → 长方向和宽方向的最大外轮廓标注值
第三步：取各方向最大整体外轮廓值，合并输出一个值，格式：长×宽×厚
规则：厚度取最薄方向整体通长尺寸，不取槽深/台阶高/局部特征深度；只抄图纸数字，不估算
```

`【尺寸公差】` 改为显式扫描清单：

```
【尺寸公差】逐张扫描以下位置：
  ① 每个尺寸数字旁的公差符号（如 ±0.05、+0.02/-0.01、H7、h6、JS6）
  ② 标题栏或技术要求区的"未注公差"说明（如"未注公差按GB/T 1804-m"）
  ③ 公差框格内的极限偏差数值
  格式：尺寸值 公差；未注公差说明；如确实无任何公差标注则填"无"
```

`【形位公差】` 改为显式扫描指令：

```
【形位公差】逐张扫描公差框格（矩形框+箭头引线），提取：类型符号（平面度/垂直度/位置度等）、
  公差值、基准代号；如确实无形位公差标注则填"无"
```

**其他字段和尾部规则保持不变。**

### 改动 2 — 输出规范化层（新增函数）

**新增函数：** `_normalize_vlm_output(fields: dict) -> dict`

**职责：** 在 `_parse_structured_fields()` 之后、下游消费之前，对解析出的字段 dict 做硬规范化。

**处理规则：**

| 规则 | 说明 | 示例 |
|------|------|------|
| 字段补全 | 20个预期字段缺失的补 `"无"` | `fields` 缺 `【刻字】` → 补入 |
| 格式标准化 | `外形尺寸` 中 `x/X/*` 统一为 `×`；裸数字补 `mm` | `120*80*50` → `长120mm×宽80mm×高50mm` |
| 数值精度统一 | 尺寸数值四舍五入到 0.5mm 精度 | `12.3` → `12.5`；`12.1` → `12.0` |
| 单位补全 | 数字后无单位则补 `mm` | `M6深15` → `M6深15mm` |
| 空值统一 | `"暂无"/"无。"/"N/A"/""` → `"无"` | |
| 空白清理 | 去除字段值首尾空白、连续空格合并 | |

**预期字段列表：**
```
零件名称, 形态, 类型, 技术要求, 关键尺寸, 外形尺寸, 通孔, 沉孔沉槽,
螺纹孔, 特殊孔, 尺寸公差, 形位公差, 表面粗糙度, 表面处理, 外圆与内孔,
螺纹与螺孔, 倒角, 热处理与探伤, 过渡特征, 刻字, 其他特征
```

**位置：** 在 `_parse_structured_fields()` 返回后调用，每个提取函数（`extract_creo_primary_features` / `extract_freecad_geo_constrained_features` / `extract_vlm_features`）内部接入。

### 改动 3 — 关键字段校验与波动锁（新增函数）

**新增函数：** `_validate_and_mark_dimensions(fields: dict, cache_key: str) -> dict`

**职责：** 对外形尺寸字段做合理性检查和跨调用防抖动。

**处理规则：**

| 规则 | 说明 |
|------|------|
| 数值合理性检查 | 外形尺寸中最小值（厚度）> 100mm 或 < 2mm → 值后追加 `[?]` |
| 跨调用波动锁 | 同一 cache_key 缓存上次结果；本次与上次偏差 > 10% → 沿用缓存值 |
| 视图冲突保留 | VLM 原文有 `\|` 分隔的多视图冲突 → 保留，不吞掉信息 |
| 修正标记 | 字段被修正过 → 末尾追加修正原因标记 |

**波动锁缓存：** 使用内存 dict（`_dimension_cache: dict[str, dict]`），key 为 VLM 缓存 key，value 为上次输出的外形尺寸解析值。进程重启后缓存清空（不跨进程持久化）。

## 数据流（改后）

```
VLM 返回原始文本
  → _parse_structured_fields(raw_text)     # 已有，正则提取
  → _normalize_vlm_output(fields)           # 新增，硬规范化
  → _validate_and_mark_dimensions(fields)   # 新增，校验标记
  → 下游 merge 函数消费
```

三个提取函数均接入此流水线：
- `extract_creo_primary_features()` — VLM 语义字段走 `_extract_vlm_semantic_fields` 内部已调用 `_parse_structured_fields`，需在返回后追加规范化+校验
- `extract_freecad_geo_constrained_features()` — 同上
- `extract_vlm_features()` — 同上

## 风险

- 数值精度统一到 0.5mm 可能抹掉精确的小数标注（如 `12.3mm` → `12.5mm`），公差字段中这类精确值居多，因此精度统一仅应用于 `外形尺寸` 和 `关键尺寸` 中的裸数字，不处理公差标注中的数值
- 波动锁依赖内存缓存，进程重启后首次调用无历史值可参照，属于可接受的一次性降级
- 这些改动不修改 VLM 本身的识别能力，不可能完全消除 VLM 读错的情况——只是在输出侧兜底
