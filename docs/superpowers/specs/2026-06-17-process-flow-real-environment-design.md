# 工艺生成真实环境修复设计

## 目标

在真实安装版后端和重新打包后的完整程序中修复工艺生成链路，并以用户可见行为验收，不以 Mock API 或组件级模拟结果代替。

## 真实环境

- 开发源码：`F:\Work_Dir\2D-v\frontend`
- 安装包工程：`F:\Work_Dir\React-p`
- 当前安装版参考：`F:\小桌面\TEST\03\SmartProcess`
- 真实后端：安装版 Python 后端，端口 `5090`
- 浏览器测试：Playwright 连接真实接口和真实 EventSource
- 禁止：Mock API、替换 EventSource、伪造完成事件、只测试静态页面

## 状态流

唯一正确流程：

`上传图纸 -> YOLO审阅 -> 特征审阅 -> 确认特征并继续 -> 工艺规程流式生成 -> 100%完成`

- 收到 `annotation_required`：显示并切换到 `YOLO审阅`。
- 完成标注并收到 `review_required`：自动切换到 `特征审阅`。
- 点击“确认特征并继续”：只提交一次 review，并立即切换到 `工艺规程`。
- 收到工艺流式数据：只更新工艺规程内容，不改变用户主动选择的 Tab。
- 收到后端完成事件且前端流式队列排空：显示 `100%` 和最终可编辑工艺表。

## Tab 约束

Tab 只负责视图显隐，不能承担业务触发职责。

- 切换 Tab 不发送 upload、review、rerun、finalize 或其他生成请求。
- 切换 Tab 不创建新的 EventSource。
- 切换 Tab 不关闭当前 EventSource。
- 切换 Tab 不重置 `ProcessPanel`、打字队列、已显示工序、进度或滚动位置。
- 三个业务面板在任务期间保持挂载，通过显隐切换视图。

## 流式显示

- 工序按稳定标识合并，优先使用工序号。
- 已显示工序不得因后续 chunk 或最终结果而消失。
- 新工序追加到稳定列表；同工序后续内容只更新对应行。
- 最终结果只用于校准和补齐，不得瞬间替换正在显示的整张表。
- 后端完成后，等待当前动画队列排空，再一次性进入编辑完成态。
- 进度必须单调递增，不允许回退。
- 后端未完成时最高为 `99%`；后端完成且队列排空后立即为 `100%`。

## 真实验收用例

1. 上传真实工程图，确认出现并自动进入 YOLO审阅。
2. 完成标注，确认自动进入特征审阅。
3. 点击“确认特征并继续”，确认只产生一次 review 请求并进入工艺规程。
4. 流式生成期间反复切换三个 Tab，确认没有新增业务请求或 EventSource。
5. 返回工艺规程，确认工序数量、内容、进度和滚动状态保持。
6. 逐帧记录工序数量，确认数量不回退且无整表闪烁。
7. 确认最终任务状态为 completed，页面显示100%，工序数量与真实结果一致。
8. 重新构建并通过 `F:\Work_Dir\React-p` 生成安装包。
9. 安装到独立验收目录，直接访问安装程序的 `5090` 页面，重复以上完整流程。
