# 工艺最终结果覆盖流式正确内容修复设计

## 问题

工艺生成阶段通过 SSE 输出的 0010 工序正确：

`下料，按图纸尺寸准备12Cr1MoVG无缝钢管，规格为φ273×40，长度10630mm`

但任务完成后，`ProcessGenerator._post_check_process()` 将特征报告中的
`【第1页摘要】`误识别为毛坯尺寸约束。摘要同时包含“毛坯类型”和尺寸文本，
导致整段摘要被当作 `blank_size`，最终覆盖 0010。前端随后使用最终
`result.json` 对账，因此正确的流式行被错误的最终行替换。

## 修复范围

采用后端方案：

1. 毛坯约束提取只接受明确的毛坯规格，不接受仅因字段中出现“毛坯”关键词而命中的整段摘要。
2. `_post_check_process()` 在覆盖 0010 前验证权威毛坯值确实是紧凑、可识别的尺寸规格。
3. 保留已有的板料、圆棒毛坯尺寸纠错能力。
4. 不修改 SSE 事件、节流间隔、逐行输出、前端动画或最终结果对账逻辑。

## 数据流

`特征报告 → _extract_process_constraints → hard_constraints.blank_size`

`LLM 工艺文本 → _post_check_process → 最终 process_flow_raw`

修复后，只有合法毛坯规格能进入覆盖路径；无合法规格时保留 LLM 已生成的
0010 内容。因此流式文本与最终保存结果保持一致。

## 回归测试

新增测试覆盖：

1. 含“毛坯类型”和大量尺寸的页面摘要不能成为 `blank_size`。
2. 本次真实圆筒图纸的正确 0010 不被页面摘要覆盖。
3. 明确的板料规格仍能覆盖错误尺寸。
4. 明确的圆棒规格仍能覆盖错误尺寸。
5. 现有工艺生成测试全部通过。

## YOLO

YOLO 加载失败与本问题独立。当前仓库缺少 `db_data/best.pt` 和
`db_data/best.onnx`，虚拟环境也未安装 `ultralytics`。本次修复不处理
模型文件或依赖安装。
