# FORGE 旧版工作台与 v1 工作流融合设计

## 目标

恢复旧版“工艺生成”页的工程工作台体验，但继续使用已完成的 v1 快照、SSE、命令、恢复和安全边界。融合后的页面应让工艺工程师感到是旧版的自然升级，而不是一个为 API 验收而搭建的新产品。

## 设计决策

选择“旧版交互壳 + 新版工作流内核”。

- 旧版是视觉密度、步骤节奏和工作区布局的参考实现。
- v1 workflow controller 是任务状态、运输、命令和恢复的唯一真实来源。
- 不恢复旧页的轮询、EventSource query token、Markdown 特征解析、重复状态机或组件内直接 fetch。
- 不保留当前 v1 验证页的大卡片线性布局。

## 信息架构

页面始终保留顶部标题和四步导航：

1. 上传图纸
2. 特征标注
3. 审阅确认
4. 工艺生成

已完成步骤可返回查看。返回只改变页面视图，不重放上传、确认标注或审阅命令。未到达步骤不可跳转。页面将后端 task state 映射为“最高已到达步骤”，并另行保留用户当前查看的步骤，两者不混用。

## 步骤体验

### 上传图纸

- 恢复旧版大面积上传区和文件摘要。
- 上传后不离开工作台；步骤条和当前文件始终可见。
- 不在前端伪造处理阶段、时间或置信度。

### 特征标注

- 桌面端采用左侧图纸工作区、右侧标注概要与操作区。
- 图纸预览是主内容，支持适应宽度、放大查看和多页切换；仍通过 workflow client 鉴权加载。
- “确认标注”只能提交一次。命令成功后立即进入处理反馈，不留下可重复点击的按钮。

### 审阅确认

- 恢复旧版审阅工作区的编辑节奏，但不呈现原始 Markdown 作为主结果。
- 特征以结构化行呈现：类型、数值、公差、来源页、证据、置信度或缺失原因、人工审阅状态。
- 支持单行修正和整体确认；提交时发送结构化 features。

### 工艺生成

- 恢复旧版工艺结果工作台，不使用相同卡片堆叠代替主表格。
- 工序使用 v1 `process_operations`，显示工序号、名称、内容、设备、工时和来源。
- 生成中显示真实阶段和进度；不将原始 token 流当作用户界面。
- 完成后提供 PDF 导出和来源追溯入口。

## 全局状态与反馈

- 将技术状态翻译为用户语言：`connected/reconnecting/closed` 不直接显示在主界面。
- 连接正常时不显示技术标签；重连时显示“正在恢复实时进度”；终止状态显示业务结果。
- 错误在所属步骤内呈现，包含可恢复动作，不只显示后端英文。
- 取消任务自动清理 active task 并返回上传步骤。
- 刷新浏览器恢复同一 task 及其最高已到达步骤。

## 组件边界

- `GeneratePage`：页面编排、当前查看步骤和 controller 生命周期。
- `WorkflowStepper`：步骤状态、可返回规则和键盘操作。
- `DrawingWorkspace`：鉴权预览、多页导航和全屏查看。
- `FeatureReviewWorkspace`：结构化特征查看、修正和确认。
- `ProcessWorkspace`：工序表、生成状态、来源和导出。
- `WorkflowFeedback`：阶段进度、重连、空状态和错误操作。

业务组件不直接访问 HTTP、SSE、localStorage 或 legacy API。它们只接收规范化的 snapshot/state 和回调。

## 视觉系统

- 继续使用项目现有深色工业色板、字体和 AppShell，不创建独立主题。
- 参考旧版的紧凑尺度、步骤节奏和主次对比，减少同质卡片。
- 强调色仅用于当前步骤、主操作和状态。
- 桌面端优先高密度工作台；窄屏将左右工作区改为上下排列，不缩小主要操作。
- 动效只用于步骤切换、处理状态和预览展开，150–250ms，遵循 reduced motion。

## 数据流

1. `GeneratePage` 创建并订阅 `DrawingWorkflowController`。
2. controller 通过 `DrawingWorkflowClient` 执行 v1 命令、读取 snapshot 并消费 SSE。
3. reducer 保持 revision/seq 单调、任务隔离、工序 upsert 和结构化错误。
4. 页面根据 task state 计算最高已到达步骤，但使用独立 view step 支持返回查看。
5. 子组件消费结构化 props，不重复解析后端数据。

## 可维护性规则

- `LegacyGeneratePage` 仅作为对照和现有回退开关，不从中 import 业务函数。
- 允许提取旧版的纯视觉模式，但必须重写为 typed props 组件。
- 禁止在页面中增加轮询、直接 fetch、EventSource、Markdown 解析或第二套任务状态。
- 单个新组件聚焦一个工作区，避免重新生成上千行页面。

## 验收标准

- 初次用户可从上传步骤完整走到 PDF 导出。
- 使用真实 `test.png` 验证四步流程。
- 已完成步骤可返回查看，且不产生重复命令。
- 刷新页面恢复同一任务和正确步骤。
- 取消任务后回到上传步骤，不再显示技术 `closed/seq` 文案。
- 标注确认和审阅确认均无重复提交窗口。
- 特征和工序仅来自 v1 结构化字段，不伪造置信度、页码或工时。
- 预览仍遵守同源、当前 task 和资产路径校验。
- 桌面和窄屏布局可用，键盘焦点可见，文字对比度符合 WCAG 2.2 AA。
- workflow tests、TypeScript、改动文件 ESLint、production build 和真实 Playwright E2E 通过。

## 非目标

- 不在本次重写识别模型、提示词、工艺核心算法或数据库模型。
- 不新增一套与 AppShell 冲突的全局导航或主题。
- 不将 Lusion 营销站特效引入工程任务页。
- 不恢复旧版的不安全或不可恢复数据流。
