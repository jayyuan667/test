# 数据隔离一期 交接文档

> 2026-06-26 | 分支 `yolo-react` | 接手人请先读完再动手

---

## 1. 做了什么

在现有 SQLite 架构上加了企业级数据隔离，不改数据库文件结构。

**三层防线：**

| 层 | 机制 | 效果 |
|---|---|---|
| DB | 6 张业务表加 `enterprise_id INTEGER` 列 | 每条数据有企业归属 |
| API | `get_enterprise_scope()` + `assert_task_access()` | 所有数据出口强制过滤 |
| 前端 | DbPage 默认选私有库、ZipPage 默认不复制公共库 | 用户不会无意识进公共库 |

---

## 2. 数据库文件（3 个 SQLite）

```
backend/auth.db          → 用户/企业/授权/配额（已有 enterprise_id）
backend/task_store.db    → 任务/事件/结果（tasks 表新增 enterprise_id）
db_data/2d-v.db          → 知识库 scope/向量/导入批次（新增 enterprise_id）
```

**加了 enterprise_id 的表：**
- `tasks`（task_store.db）
- `kb_library_scopes`、`kb_import_batches`、`vectors_v2`、`vectors_<key>`（2d-v.db）

**没加的表（通过 JOIN 获取归属）：**
- `task_events`、`task_results`、`prt_cache`、`kb_import_items`

## 3. 关键文件

| 文件 | 作用 |
|---|---|
| `backend/api/_utils.py` | `get_enterprise_scope()` — 从登录态取企业ID<br>`assert_task_access(task_id)` — task 归属校验 |

| `backend/history.py` | `get_history(enterprise_id=?)` — 应用层过滤 |
| `backend/api/upload.py` | 上传时写入 enterprise_id |
| `backend/api/kb_import.py` | ZIP 导入时写入 enterprise_id |
| `backend/migrations/001_add_enterprise_id.py` | 幂等迁移脚本 |
| `backend/migrations/001_verify.py` | 迁移后验证 |

## 4. 隔离规则（核心）

```
enterprise_id = 具体值     → 属于该企业，仅本企业可见
enterprise_id = NULL + scope_type = public  → 公共数据，所有人只读
enterprise_id = NULL + scope_type = private → orphan，仅 super_admin
```

**公共库判定方式：** 用 `scope_type = 'public'`，**不用** `enterprise_id IS NULL`。

**权限矩阵：**

| 角色 | 本企业私有库 | 公共库 | 其他企业 | orphan |
|------|:---------:|:-----:|:------:|:-----:|
| super_admin | ✅ | ✅ | ✅ | ✅ |
| enterprise_admin | ✅ 读写 | ✅ 只读 | ❌ | ❌ |
| user（已分配） | ✅ 只读 | ✅ 只读 | ❌ | ❌ |
| user（未分配） | ❌ | ✅ 只读 | ❌ | ❌ |

## 10. 2026-06-26 接手复核

已执行：

```bash
uv run python backend/migrations/001_verify.py
uv run pytest backend/test_kb_import_zip_route.py backend/test_data_isolation.py backend/test_library_storage_init.py -q
```

结果：

- 迁移结构验证通过：`tasks`、`kb_library_scopes`、`kb_import_batches`、所有 `vectors_*` 表均有 `enterprise_id`。
- 数据隔离相关测试通过：19 passed, 1 skipped。
- skipped 原因：本地 `vectors.db` 仍有 2 个历史 private scope 的 `enterprise_id=NULL`，无法在该环境验证“未分配用户只看公共库”。

当前剩余数据状态：

- `backend/task_store.db`：15 条 `tasks.enterprise_id IS NULL`。
- `db_data/2d-v.db`：2 个 private scope 的 `enterprise_id IS NULL`。
- `db_data/2d-v.db`：5 条 `kb_import_batches.enterprise_id IS NULL`。

处理建议：

- 不要自动把 NULL 归到某个企业，避免错分历史数据。
- 上线前由管理员确认这些历史数据是公共数据、废弃数据，还是归属某个具体企业，再执行回填或清理。
